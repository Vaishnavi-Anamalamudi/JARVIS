# Phase 6: Redis Integration

## Objective

Integrate real Redis into the backend runtime for short-lived operational state while keeping PostgreSQL as the system of record.

This phase does not implement Kafka, rate limiting decisions, adaptive learning, anomaly detection, API consumer credentials, frontend, WebSocket, analytics screens, request-log persistence, or deployment.

## Added Backend Capabilities

- Spring Data Redis with Lettuce through Spring Boot.
- Environment-driven Redis connection configuration.
- Validated Redis integration properties.
- Versioned Redis key namespace service.
- Redis health verification through a real write/read round trip.
- Redis session cache snapshots written when auth tokens are issued.
- Redis session cache eviction on logout.
- Temporary Redis stats service for later rate-limit and dashboard phases.
- Structured `REDIS_UNAVAILABLE` error code.
- Redis details included in `GET /api/system/health`.

## Redis Key Strategy

Redis keys are generated by `RedisKeyService` using the configured prefix:

```text
{ADAPTIVE_GATEWAY_REDIS_KEY_PREFIX}:{domain}:{key-parts}
```

Examples:

```text
agw:v1:auth:session:{userId}
agw:v1:stats:{domain}:{metric}:{identifier}
agw:v1:system:health
```

Redis is not used as the source of truth for durable business entities.

## Auth Session Cache

Authentication remains PostgreSQL-backed.

When access and refresh tokens are issued, Redis stores a short-lived session snapshot containing:

- user id
- username
- email
- role
- account status
- last login timestamp
- token expiry timestamps
- cache timestamp

Logout revokes the durable refresh token in PostgreSQL and evicts the user's Redis session snapshot.

## System Health

`GET /api/system/health` now verifies:

- backend status
- PostgreSQL status
- Redis status

Redis health performs a real write/read operation with a short TTL.

## Environment Variables

Phase 6 adds these required variables:

```text
REDIS_URL
REDIS_COMMAND_TIMEOUT_MS
ADAPTIVE_GATEWAY_REDIS_KEY_PREFIX
REDIS_SESSION_CACHE_TTL_MINUTES
REDIS_TEMPORARY_STATS_TTL_MINUTES
```

## Verification

Verified in this phase:

- Backend compilation.
- Unit test execution.
- Redis key namespace generation.
- Redis session cache JSON write/read behavior.
- Auth service writes Redis session snapshots when issuing tokens.
- Auth service evicts Redis session snapshots on logout.
- Static scan for forbidden implementation markers.

Runtime Redis verification still requires a real Redis instance plus the required environment variables. No embedded Redis or in-memory fallback was added.
